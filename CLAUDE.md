# House Design App: map for Claude

Next.js 15 + React 19 + TypeScript app that runs locally in a desktop browser (single user, no server data, no API keys). Tailwind, Zustand, Dexie (IndexedDB), Zod, react-konva (2D canvases), React Three Fiber + drei (3D), Vitest.

Read this file first, then open only the files for the feature you're changing. Don't explore the whole repo. README.md is for the user; its "For developers" section has longer notes on how each `lib/` folder works, if this map isn't enough.

## Saving tokens (please follow)

- **Don't read these whole:** `package-lock.json`, `data/catalog/*.json` (look at one entry with `head -40`, or use `jq`), `lib/cost/data/cost-rates.json` (`jq '.rates | keys'`, or grep for one rate), `lib/codes/data/irc-2021.json` (grep for the key you need), `lib/location/data/cities.json` (grep for one city id), `lib/codes/data/local/*.json` (one state or city file at a time, found by id), `app/favicon.ico`.
- **Big files** (open the part you need with a line range or grep, not the whole file): `lib/plan/devices.ts`, `components/plan/useGestures.ts`, `lib/codes/rules.ts`, `lib/model/schema.ts`, `components/bubbles/SketchCanvas.tsx`, `components/plan/PlanStage.tsx`, `components/house3d/House3DView.tsx`, `lib/plans/sheets/floorPlan.ts`, `components/plan/PlanSidePanel.tsx`, `components/bubbles/BubbleStage.tsx`, `lib/plans/scene.ts`, `lib/plan/cabinets.ts`.
- **Tests:** while working, run only the related file, e.g. `npx vitest run tests/plan.test.ts`. Run the full `npm test` once before opening a PR, and print only the summary (`npm test 2>&1 | tail -15`).
- **Build and lint:** `npm run build 2>&1 | tail -20`, `npm run lint 2>&1 | tail -20`. Run them once near the end, not after every edit.
- **Browser checks:** a few screenshots of what changed, not every screen. Chromium is at `/opt/pw-browsers` for Playwright.
- **Research** (product prices, links, building rules) goes to a helper agent that returns only the final data, so web pages stay out of the main conversation.

## Conventions

- All lengths are **inches** (`lib/model/units.ts` formats feet and inches). Typed lengths all go through `parseFeetInches` there (a plain number is feet, inches need `"`, `12 6` = 12' 6"); `lengthPreview` gives the live "= 12' 6"" text, and `LengthField` (PlanSidePanel) is the side-panel box. Plan and sketch coordinates: x east, y south.
- The saved project is one Zod object in `lib/model/schema.ts`. Changing its shape means bumping `SCHEMA_VERSION` and adding a migration in `lib/model/project.ts`.
- Every edit goes through `useProjectStore().update(...)` in `lib/store/projectStore.ts` (undo history + autosave). Undo labels come from `lib/store/describe.ts`.
- Logic lives in `lib/` as plain functions with tests in `tests/`; `components/` is UI. 3D and Konva components load with `dynamic(..., { ssr: false })`.
- Kept answers: `planWarnings` reuses each floor's warnings while what `levelDeps` (in `lib/plan/checks.ts`) lists is unchanged, so a check that starts reading another floor must add it there; `measureHouse` keeps its last 8 answers; the Plans page preview draws only the shown sheet (`buildSet`'s `draw`).
- Taking a floor away asks first (`BriefStage` `setAnswers`, `BubbleStage` `removeLevel`): `lib/brief/levels.ts` `removedLevelIds`, `roomsOnLevels`, `dropLevelRooms` (clears that floor's sketch and floor plan in the same undo step), `removeRoomsQuestion`. No answer keeps the floor.
- Page shortcuts: every page's key listener starts with `keyIsForPage(e, { here })` from `lib/keys.ts` (not typing in a box, no `aria-modal` dialog or `data-over-page` view like the walkthrough or Plans page over it, unless `here`, the listener's own element, is inside it).
- Everything is worked out by code. No Claude/AI calls and no API keys in the app.
- Each change: its own branch and PR. The user (Grant, on a Mac, new to dev tools) tests locally; his steps always include `git pull` and `npm install`.
